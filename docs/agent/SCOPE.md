不创建没有实际用途的文件或组件。学习记录、复杂语音服务、其他 AI 平台、真实扣子后端等一律不提前建设。

## 明确禁止

1. 不为了架构形式创建不必要的抽象。P1 只留入口，不建空壳目录或空组件。
2. Feature 之间不直接 import；页面不直接操作业务逻辑；状态只经 Commands 修改；外部能力只经 Ports。
3. Mock 数据独立放在 `data/`，不得写进 UI 组件。
4. 功能注册（`features/registry.js`）与页面组合（`pages/*.js`）分离。
5. 不引入任何运行时依赖或构建工具（零依赖）。
6. 接口返回文本一律 `textContent`，禁止 `innerHTML` 拼接。
7. 不提交令牌；`web/config/config.local.js` 保持在 `.gitignore`。
8. 首页滤镜出现明显性能问题前，不得擅自简化；降级方案是预渲染纹理 WebP，仅在实测卡顿后启用。
9. 开发期间不对外公开部署带 `debug: true` 的构建；最终部署前把 `flags.debug` 改为 `false`。
10. 不在同一个任务里同时开发工作台状态机和首页 SVG（见 PLAN.md 的任务边界）。

## 架构约束（保留技术文档 14.2–14.7 的核心规则）

```
pages → features → core ← adapters
  app.js 组装根：依赖注入、读取配置、挂载页面（唯一同时看见 adapters 与 features）
```

- `check-deps.mjs` 强制：core 无浏览器全局；adapters 不 import features；features 之间不互相 import；features / pages 不 import adapters。
- 不要求本次完整实现适配器契约测试，只保留 `config.test.mjs` 做配置自检。
- 页面（`pages/*.js`）只描述"用哪些功能、放哪个槽位"，不含业务逻辑。
